# 提案视觉制作

## 本工作包入口

这是 Huashu 的项目适配版，不是另一个总控。先读根目录 `AGENTS.md`、[html-deck](../html-deck/SKILL.md) 和 [执行说明](references/harness-deck.md)，再完整读取本任务简报、当前逐字稿、品牌屋、推导、来源及实际确认记录。上游固定版本见 [SOURCE.md](SOURCE.md)。

`proposal-author` 写逐字稿，`deck-builder` 用本 Skill 制作视觉候选，总控登记正式版本，另一名 `independent-reviewer` 检核全部正式产出，策略师单独确认演示稿。作者不能自审、改公共状态、再派子 Agent 或借换角色名绕过检核；没有独立实例时停在待检稿。

复用已确认品牌调性、简报、具体参考和自主选择授权；方向来源如实记录。只有无法查清、且会明显改变结果的选择才询问，不强制每次三套方案或十个问题。不因运行模型名称跳过确认或降低检查标准。

## 正式制作路线

1. 逐字稿未确认或上游过期时，停止正式制作，回到 `proposal-script`。不得在视觉阶段改标题、听众、目的、正文、转场、证据与客户承诺。
2. 本版正式路线沿用 `templates/proposal-deck.html` 的单文件结构。先制作 `page_plan`，把画面要点、讲者稿、表格/图表/图片与论断来源分开；允许忠实提炼，不允许改结论或补事实。格式见 `../html-deck/references/page-plan.md`。再准备字体、色彩、留白、版式及信息层级的 CSS 候选；不另造一个未登记的“最终视觉稿”。
3. 将页级方案、已核对指纹的本地图片及 CSS 的 `visual_style` 一并提交总控运行 `deck-generate`。CSS、完整内容、映射和图片一起固化为正式 `presentation.html` 与版本历史。只改视觉也创建新版，不继承旧报告或确认。
4. 总控对这份正式 HTML 运行 `deck-browser-check`。独立实例读取全部来源、实际最终 HTML 和逐页截图，检查内容是否被隐藏、遮挡、截断或造成误读，完成正式报告后交策略师单独确认。
5. 从已确认的正式 HTML 用工作包 `scripts/deck_export.py` 导出 PDF，再核对实际页数、正文、布局及导出清单。上游多文件和 `deck-stage` 导出脚本不能直接用于本模板。

精确字段、命令和失败处理见执行说明。策略师只需在对话中说明需求，不需手写请求。

## 按需设计参考

- 视觉层级与中文排印：`references/typography.md`、`references/content-guidelines.md`。
- 幻灯片构图：`references/slide-decks.md`；其中多文件、独立 JS 与概览墙是设计参考，不覆盖本版正式结构。
- 缺少视觉方向时参考 `references/design-styles.md`，不加载所有示例或冒用其他项目资产。
- 实际检查：`references/verification.md`；设计诊断可参考 `references/critique-guide.md`，不能替代工作包独立报告。
- 只有明确要求扩展交付时，才读 `UPSTREAM.md` 和对应 PPTX 参考。自由布局多文件与 PPTX 尚未接入本版正式版本门禁，只能标记为扩展候选，另行验收；本地静态图片仅通过 page_plan.image 的受控入口嵌入。

本版样式入口不接受外链、脚本、生成文字或图片 URL。需要这些能力时先报告限制，不通过修改已登记 HTML 绕过门禁。依赖只用实际可用的本地运行时；缺少时保留失败，不安装全局 Hook，不调用收费云端、不发布、不改记忆。

## 执行契约

- **触发**：已确认逐字稿需要制作或修订提案视觉，或已确认 HTML 需要导出 PDF。
- **开始**：核对四个来源引用、实际报告和确认；完整读原文及已有方向，再选必要的设计参考。
- **产出**：视觉 CSS 候选与方向依据；总控登记的最终 HTML、历史及原文映射；逐页实测证据；确认后 PDF 与导出清单。
- **停止**：来源失效、缺必要确认、CSS 不支持、浏览器或导出失败、逐页未查时停止放行。上游变动先对齐，保留历史与失败。
- **交接**：候选和版本请求交总控，正式稿交不同独立实例检核，再由策略师确认；内容问题回逐字稿或更上游，不能用美化弥补证据不足。
