# 品牌屋正文与推导

## 依赖与边界

1. 先读 `AGENTS.md`、`project/state.json`、既有任务简报、研究证据、上游版本和反馈/确认记录。
2. 品牌屋任务必须使用既有 `task_id`，绑定当前简报和证据版本。上游版本失效、证据提取不完整或缺少关键输入时，停止正式定稿并列出缺口。
3. 只使用当前项目资料和明确标注的合成资料。其他项目只能作为方法参考，不能把客户事实、数字、能力或消费者认知带入。
4. 本 Skill 只做品牌屋正文、推导和反馈修订，不做包装或设计稿实际检核，不制作 HTML、逐字稿、PPT 或实际设计稿，不连接云端系统。

## 固定顺序与实际路径

按以下顺序写，不跳步、不把一句口号当完整品牌屋：

1. 品类定位：服务哪个品类问题、竞争范围和战略边界。
2. 目标人群：谁在什么场景下需要它，必要时区分购买者、使用者和影响者。
3. 差异化价值：明确“对谁、相较什么、为何重要、凭什么兑现”。
4. 定位身份：品牌在目标人群和竞争关系中的身份。
5. 使命、愿景、价值观：三者分别成立，不能互相改写或堆成一段漂亮话。
6. RTB：支持差异化价值的理由和证据，不能把愿望写成能力。
7. 品牌人格：可观察的行为和表达倾向，不以“像总监措辞”作为标准。
8. 内部品牌主张：给团队使用的工作主张，说明要持续做什么。
9. 外部口号：给消费者接收的表达，与内部主张分列，不强求押韵或华丽。

正式结构化产出必须使用统一入口 `scripts/phase3.py` 的对应动作，不在 Skill 中另造参数。文件由 `phase3_store.paths` 写入：`project/outputs/brand-house/<task_id>/brand-house/`、`derivation/`、`summary/`，各目录保留 `current.json`、同名 Markdown 和 `versions/`。

`brand-house` 的章节顺序必须严格为 `category`、`audience`、`differentiated_value`、`positioning`、`mission`、`vision`、`values`、`rtb`、`personality`、`proposition`、`slogan`；`derivation` 必须为 `positioning_triangle`、`identity`、`mvv`、`value_to_rtb`、`personality_proposition`、`slogan_translation`、`counterevidence`、`validation`。每章填写正文、支持证据、反证、假设和待验证列表；关键推导没有证据时，必须同时写明假设和验证方法。品牌屋直接上游必须是 `analysis`，推导直接上游必须是 `brand-house`。

## 方法参考与适配边界

本 Skill 只吸收以下全局方法的通用工作方式，不复制客户案例、资产或结论：`brand-house-assistant`（竞争战场、字段层级、当前/目标状态 RTB、逐字段检核）；`strategy-director`（把经营问题、策略选择和交付结果分开）；`copywriting-skill`（事实复核后再写说法，区分办法/看法/说法）；`packaging-expression-strategy`（包装表达前先查产品事实、渠道场景、必留信息和证据状态）。这些方法不能改变本项目固定 schema，也不能把包装表达规则扩展为设计稿实际检核。

## 证据纪律

不编数字、不编能力、不编消费者认知、不把内部意见写成市场事实。证据不足可以做假设稿，但标题和正文都要显式标记 `hypothesis` 或“假设稿”，并说明需要谁、通过什么材料或行动验证。对证据只能支持阶段性结果的地方，使用“初步”“待验证”等准确措辞。

RTB 必须能回到差异化价值；如果只能证明一般品质、一般服务或企业愿望，就不能冒充差异化理由。反证、矛盾和不确定性要保留，必要时提出少量启发问题，不用多数投票消灭分歧。

## 反馈修订

收到反馈先判断是否涉及事实、策略方向、结构、措辞或未决歧义。歧义会改变结果时先问；能确定的部分先改稿，再提出少量启发问题。每次修订都保留：原反馈、对应旧内容、对应新内容、修改原因、引用证据或待验证安排。不得只改一句而让下游定位、RTB、人格、主张和口号脱节。

正式品牌屋由不同 fresh 实例独立检核；作者不能自审。检核重点是顺序完整、逻辑可推导、证据可回查、假设有标记、RTB支持差异化价值、内部主张与外部口号分列，以及没有把审美偏好当策略问题。最多自动业务修订两轮，每轮后先独立复核；仍有争议时保留各版本和反馈，交策略师决定。内部稿件返工不自动增加客户审批节点。

## 判断和追问契约

先给出可工作的候选稿，再追问；不能把本可由证据推导的工作全部退回给策略师。每个关键字段都按“结论、支持证据、反证或冲突、当前假设、待验证动作”组织。候选稿完成后，最多提出3—5个真正会改变结论的问题，并说明每个问题会影响哪个字段；不要用泛泛的“您怎么看”代替拷问。

逐字段追问至少覆盖以下角度：

- 品类定位：品牌实际解决的品类问题是什么，消费者的替代选择是什么，竞争边界在哪里；不能把企业自称的品类直接当成消费者选择的品类。
- 目标人群：谁在什么场景下遇到问题、谁付钱、谁使用、谁影响选择；要说明谁不是目标人群以及排除依据。
- 差异化价值：对谁、相较什么、为何重要、凭什么兑现；如果同类品牌也能直接说出这句话，退回一般利益，并继续追问独特机制和可观察证据。
- 定位身份：品类、人群和差异化价值合并后，是否能让第三者复述品牌是谁、为谁解决什么问题；不能只把三个字段拼接成口号。
- 使命、愿景、价值观：使命回答现在为何持续做，愿景回答未来要促成什么变化，价值观必须能落到取舍、行为和反例；漂亮但无法指导选择的词不算完成。
- RTB：每条理由要回答“怎么做到”和“在哪里被证明”，不能用规模、历史、专业、品质等通用能力替代兑现机制。
- 品牌人格：用可观察的行为、语气和取舍描述，而不是堆形容词；要写出一个不符合该人格的表达反例。
- 内部主张与外部口号：内部主张是团队持续做什么，外部口号是消费者能接收的表达；口号不能承担定位、证据和完整解释的全部任务。

## 执行契约

- **触发**：调研分析已形成可用版本，或已有品牌屋反馈需要修订时启动；只有查一条资料或改一个错字时，不启动完整品牌屋流程。
- **开始**：先回读当前任务、简报、证据、上游版本和反馈，列出已知、冲突、缺口，再按固定顺序生成候选品牌屋和推导。
- **产出**：至少包括正文、逐段推导、证据/反证/假设表、反馈对照和待策略师回答的问题；每个结论都能回到当前项目资料或明确标注为假设。
- **停止**：任务、证据版本、关键原文或授权缺失，或关键结论存在未说明的冲突时，停止正式定稿，保留候选稿并写明缺什么、可先做什么；不替客户或策略师编答案。
- **交接**：独立检核通过后交可编辑品牌屋；品牌屋确认后才交逐字稿。上游变化时先交版本影响检查，不直接沿用下游确认。
