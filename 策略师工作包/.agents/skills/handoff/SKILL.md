# 交接打包、任务交接与接手（v1.7.8，J01—J05；v1.7.9 小修 J07—J15）

触发语：“交接”“打包给同事”“把这个交给他”“把整个项目发给别人”等。对策略师说话按 `AGENTS.md`“对策略师说话”，三段说；下面命令与字段只给 Agent 看，不念给她听。

## 1. 先问：全量还是任务

- 一句话问：“整间办公室整个交出去，还是对方已经装好了工作包、只交其中一个任务？”从她的话里能判断就不问。
- 她选只交一个任务：走下面第 6 节“任务交接”。

## 2. 全量交接：先给看，回“好”才打包

0. **打包前先补记录**（v1.7.9 J11）：先逐个核对进行中的任务——现状、下一步、有没有在等客户或策略师答复的事。对话里有、记录里没有的（客户新意见、刚发出去等回复的修改计划），先用任务登记（`standalone_tasks.py save`，写进任务的摘要和下一步）补进记录，再预览。补不进记录、又很要紧的情况，留到“现状补充”：第 1 步给她看草稿时问她，她同意后第 3 步打包时用 `--status-note` 带上。
1. 运行 `python scripts/jiaojie_dabao.py preview --workspace . --kind full --json`（只读，不写任何文件；默认只给个数和最大几项，要把每个不带的文件都列出来加 `--list`）。把 `for_strategist` 原样转述：带走多少、不带多少、不带的是哪些（过程文件、暂存、重复副本、看名字像过程的、操作记录等，每类个数和大小，附最大几项）、拿不准的、没挂任务的大文件夹、有没有像凭据的文件、检查有没有没解决的问题。
   **再把 `note_draft`（交接说明“给接手人”那一半的草稿）用白话给她看**，问一句：“这份说明准不准？有没有最新情况要补一句？”她补的最新情况（比如客户的新意见、在等谁回复）整理成几句白话（不写任务编号、命令名），她同意后随“好”一起带上（第 3 步的 `--status-note`）；她不补就不带。
2. 她想多带或少带：把她说的文件夹名对到 `project/` 开头的路径（对照预览里的 `skipped_files`、`unregistered_dirs`，你看了名字可以**建议**，由她定）——
   - 多带（本来不带的：过程、暂存、重复副本、看名字像过程的）→ `--include <路径>`；
   - 少带（本来要带的：成品、来源、拿不准的、没挂任务的大文件夹）→ `--exclude <路径>`；记录里用到的文件和工作包本身不能不带，凭据与登录状态类永远不带。
   改完再 `preview` 一次给她看。
3. 她回“好”（当次原话）之后才运行 `python scripts/jiaojie_dabao.py pack --workspace . --kind full --words "<她的原话>" --actor <主控实例> [--to <接手人>] [--include …] [--exclude …] [--status-note "<她同意带上的现状补充>"] --json`。没有她当次的原话不打包。`--status-note` 过说人话扫描：有任务编号、命令名之类会返回 `status_note_rejected` 并说哪里要改，改成白话再来，不要硬绕。
4. 打包结果：
   - `status=packed`：把 `for_strategist` 原样转述（压缩包放哪、多大、带走多少、核对过没有损坏、原工作区一个文件都没删），再把 `forward_text`（可以直接转发给对方的话）原样给她。路径放代码块。
   - `status=needs_consent`（工作区检查有没解决的问题，**不含凭据类**）：把 `for_strategist` 转述——它已经按类别列出是什么问题（记录里写到的文件找不到、工作包本身被改过、根目录有零散文件……），**逐类念给她，不要只说“有 N 个问题”**。要她**当次**明确说“同意照原样交”才加 `--accept-problems "<她的原话>"` 重新打包；她要先修就先修。不要替她同意。
   - `status=blocked_credentials`（要带的文件里、或检查报的问题里有像密码、密钥的内容）：转述 `for_strategist`（它已经报了总数，分开说了“名字像”和“内容像”，只给走得通的出路）；**这一类她同意“原样交”也不行**，不接受 `--accept-problems`。出路按它说的：内容像的，改掉里面的内容，或她确认不是密码或密钥时登记误报；名字带中文“密码、密钥、口令、令牌”、内容干净的，她确认后可以登记（`wubao_dengji.py register --path <文件> --field （按文本检查）`，文件没变就放行，变了重新拦，含密钥样式的仍拒）；名字是英文写法（`.env`、`*.pem`、带 token / secret / password / credential 的名字）的不能登记，改名或搬出工作区——被记录用到的文件改名会让记录对不上，只能请维护工作包的人处理。**名字里带“凭证”“凭据”的不再按名字拦**，只看内容。项目记录、被改过的发行文件、工作包目录里自己加的文件都在扫描范围内。
   - `status=version_mismatch`（v1.7.9 J14）：脚本所在的工作包和这个工作区版本不同，`for_strategist` 说“这个工作区还是旧版，先升级再交接”，照说，不重试；升级是另一件事，先不动手。
   - 其他报错：照实白话转述，不重试同一条。
   - 压缩包大于 30MB 时，结果里的 `for_strategist` 和 `forward_text` 多一句：文件较大，聊天里可能发不了，建议放云盘发链接、只给对方一人查看（v1.7.9 J15），照转述。
5. 打包只多两样东西：项目记录里的交接说明（`project/records/交接说明/`，双读者，随包）和一条交出记录（`project/records/handoff-out.jsonl`，不随包）。原工作区的文件一个都不删、不改。交接说明里任务按“进行中在前、最近更新在前、已完成在后”排，已完成多于 5 个的只列最近 5 个（名字见技术附录）。

## 3. 交出之后

- 续做状态（`project_handoff.py resume`）输出里有 `handed_over` 时，顶部先转述那句：“这份已经交出去了……你在这里改的东西，对方看不到”。只提醒，不阻断。要让对方拿到新进展，需要再交接一次（新包不覆盖旧包，名字加序号）。
- 想核对压缩包有没有损坏：`python scripts/jiaojie_dabao.py verify --package <压缩包路径>`（不解压）。

## 4. 带什么、不带什么（给 Agent 看）

- 全盘细查 r2 起：留下的成品页面（HTML / CSS / SVG / Markdown）里用到的图片、样式、字体（`src`、`href`、`url()`、引号里的相对文件名，顺着样式表继续找）算“记录里用到的文件”，不移、全量与任务交接都照带；两份同内容的图，留被页面引用的那份。预览里单列“被成品页面引用、因此不移”。

- 带：工作包本身（规则、技能、脚本、模板）、项目记录与状态、成品、来源资料、记录里用到的文件（含放在“过程”里但被检核基线、发客户记录等引用的）、拿不准的文件（默认带）、没挂任务的大文件夹里除暂存 / 重复副本 / 看名字像过程的以外的部分（默认带）。
- 不带：“过程”文件夹里没被引用的、暂存、同内容的多余副本（每组留的那份照带）、看名字像过程的（默认不带）、操作记录（运行日志）、锁文件、缓存与运行环境、凭据与登录状态类文件、符号链接、本机交出记录；工作区外的备份与归档本来就不在工作区里。
- 分类与保护规则同“过程文件整理”（`scripts/guocheng_zhengli.py`），一条不放宽。清单与指纹沿用移交清单，另写明每个没带的文件；对方解压后用 `project_handoff.py accept --manifest-id <编号>` 核对。

## 5. 接手：对方说“接手”“接手这个交接包”（J04，N5）

对方在自己选的工作区（或空文件夹）里打开对话，把交接包拖进来或说出它的位置，说“接手”。**你不替他选工作区，他没选之前不写任何文件。** 每一步都用白话告诉他：你现在在做什么、为什么停下、他要选什么。命令只给你看，不念给他听。

三个命令（都加 `--workspace .`，输出 JSON，`for_strategist` 原样转述给他）：

1. **找包**：`python scripts/jiaojie_yindao.py find --workspace . [--package <路径>]`。他给了路径就用他给的（对话附件的实际位置两个宿主不一样，以他给的或附件显示的为准）；没给就在当前文件夹和上一级找名字里带“交接”的压缩包；找到多个（`choose_package`）就列出来问他是哪个，找不到（`none`）就请他把压缩包放进当前文件夹再说一次“接手”。已经接过的包不再当候选。
2. **看清情况（只读）**：`python scripts/jiaojie_yindao.py guide --workspace . [--package <压缩包>] --json`。它先核对压缩包，再看压缩包的类型和当前文件夹，返回 `situation`（现在是哪种情况）、`options`（他可以选哪几个）、`for_strategist`（要转述的话）。**guide 不写任何文件**；不替他选，转述后等他回答。
3. **他选了才动手**：`python scripts/jiaojie_yindao.py receive --workspace . --package <压缩包> --choice <选项> --words "<他当次的原话>" --actor <主控实例> [--name <他的称呼>] [--from-who <谁交给他的>] --json`。每个会写文件的选项都要他当次原话；开口问他“怎么称呼你？这个包是谁交给你的？”（不说就记“接手人”“交出的人”）。

各种情况（`situation` → 对他说什么 → 选项 `choice`）：

| 情况 | 怎么办 |
|---|---|
| 包坏了或被改过（`package_damaged`，status=refuse） | 原样转述：压缩包坏了或被改过，我不敢解开，没动你任何文件，请找原来的人重新发一份。**不解开、不写文件。** |
| 看不懂的包（`unsupported_package`） | 原样转述，不写文件 |
| 全量包，当前文件夹是空的（`full_empty`） | 问：解到现在这个文件夹（`full_here`），还是解到旁边一个新文件夹（`full_beside`）？ |
| 全量包，当前文件夹里有别的东西（含别的交接压缩包）、但还不是工作区（`full_other`） | 说明“这个文件夹里已经有别的东西，整间办公室直接铺在这里会混在一起”，推荐放进里面一个新子文件夹（`full_here`，原有的东西一个字节不动），也可以解到旁边（`full_beside`）。解开后以后就在放它的那个文件夹打开对话 |
| 全量包，当前文件夹已有自己的案子（`full_mixing`） | 说明“这是一整间办公室，放进来会和你现在的案子混在一起”，建议解到旁边新文件夹（`full_beside`，名字不覆盖，告诉他以后在那个文件夹打开对话）；他**坚持**才选 `full_here`：已有的文件一个字节不动、绝不盖掉；工作区里放不进去（`insist_blocked`）就如实说并回到旁边；有别的东西的普通文件夹放进里面一个新子文件夹。原话会记录 |
| 全量包，当前文件夹本身就是解压好的包（`full_unzipped_here`） | `accept_here`：直接核对并接手 |
| 任务包，当前文件夹没装工作包（`install_first`，info） | 说明要先装同一个版本的工作包，把 `for_strategist` 里“安装”那一句话给他；或建议他请对方改发全量交接。不写文件 |
| 任务包，你的工作包比包旧（`upgrade_first`，info） | 先升级（给更新那一句话）再接；你的工作包比包新，说明后照常接（记录格式不兼容就停下说明） |
| 同一个客户、空白工作区、你这边有旧版（`same_client` / `blank` / `blank_no_identity` / `append_newer`） | 说“接手”的话：`import` |
| 比对不了是不是同一个客户（`identity_unknown`） | 问是哪个客户项目：`identity_same`（他当次明确说就是）/ `new_workspace` / `switch` |
| **不同客户**（`different_client`） | 说“这个任务属于 X 客户，你现在打开的是 Y 客户的工作区”，三选项，**未选之前不写任何文件**：①`new_workspace` 在旁边新开 X 客户的工作区（推荐；用已装的工作包复制一份，**只复制工作包本身，不复制 Y 的资料和记录**，名字不覆盖，导入后告诉他以后在哪个文件夹打开对话）；②`switch` 换到别的工作区再接手（这次什么都不做）；③`mix_here` 坚持放在这里（先说后果：两个客户的资料混在一起，他回原话后导入；导入事件记他的原话和原客户身份，项目记忆不合并、只进备查；放进来会盖掉他的文件时这一项不给） |
| 同编号任务两边各改过（`task_diverged`） | 两选项：`fork_keep_mine` 保留你这边的、不导入（压缩包留作备查，记他的决定）；`fork_save_new` 另存为新任务（新编号，来源指向导入的只读副本，旧历史在 `project/records/handoff-imports/`） |
| 已经接过（`already_imported`）/ 你这边已有同样或更新的（`nothing_to_import`） | 原样转述，不用再接 |
| 其他要停下的（`file_conflict`、`request_conflict`、`receiver_has_problems`；解开时发现位置上已有同名但内容不同的文件 `extract_conflict`） | 原样转述（`extract_conflict` 会说是哪些文件、一个都没写），不写文件，不替他换工作区 |

**接好之后**（`receive` 的结果 `status=received`）：把 `for_strategist` 里的三句话——现在到哪了 / 要你做什么 / 下一步——原样转述（它们取自交接说明“给接手人”那一半）；程序已经追加了接手记录（`project/records/handoff-received.jsonl`：谁、哪天、从谁那里接手、原话、选了哪个选项）；提醒他飞书、云端大脑、产品线网站这类账号要用自己的账号连（要用产品线网站就说“帮我连产品线网站”）；`received_with_errors` 时如实告诉他有几个检查问题、先别往下做。全量包同样。

**同一客户已有项目记忆时逐条选**：任务包接好后，`for_strategist` 会逐条列“包里这样说 / 你这里这样说”（先列 10 条，其余说还有几条），你原样转述；他说“第 N 条用包里的”（几条都行）时运行 `python scripts/jiaojie_yindao.py memory-choose --workspace . --import-id <receive 结果里的 import_id> --numbers <序号,序号> --words "<他当次的原话>" --actor <主控实例> --json`，程序用现有的项目记忆登记（`project_memory.py save`）追加一条“待确认”的记录、记他的原话，他原来的记忆一个字节不改；同一条再来一次不重复追加。他不说就保持他那边的，不替他选。

**全量接手后原来那位说过的话不生效**：全量包接手时程序追加了接手记录；之后发客户的门槛对“接手记录之前”的豁免（“这版不用检查直接发”）、最终版、不用查、已看到提醒不再算数（历史照常能看，检核按内容仍算数），新接手人要用得自己再说一次。告诉他这一点。压缩包如果就放在工作区根目录，程序会把它挪到文件夹旁边（不删），这样工作区的检查不会因它报错。

没有这个技能时（对方的文件夹是空的、AI 助手不认识“接手”）：先把全量交接包解压到旁边一个新文件夹，在那个新文件夹里打开对话再说“接手”，新文件夹里带着本技能和全部说明。

## 6. 任务交接（N4）：只交一个任务

1. `python scripts/jiaojie_dabao.py preview --workspace . --kind task --json`（不带任务编号）：列出本项目的任务让她选，`for_strategist` 原样转述。**没登记成任务的成果**先问“要不要先把它登记成一个任务再交”，她同意才 `python scripts/jiaojie_dabao.py register-task --workspace . --dir <project/ 开头的文件夹> --title <任务名> --words "<她同意的当次原话>" --actor <主控实例>`（原话记进登记）。
1a. **打包前先补记录**（v1.7.9 J11）：核对这个任务的现状、下一步、有没有在等客户或策略师答复的事；对话里有、记录里没有的，先用任务登记补进记录，再预览。
2. 选好后 `preview --kind task --task <任务编号> --json` 先给看：带走多少、依赖的前序成果（只读参考）、不带的过程 / 暂存、**不会带过去的决定**（豁免、最终版、确认；对方要用得自己再说一次）、检核没问题且成品字节不变的对方不用重检、门槛不放宽。把 `for_strategist` 原样转述，再把 `note_draft`（交接说明“给接手人”那一半的草稿）用白话给她看，问有没有最新情况要补一句；她同意的补充随“好”一起带上（`--status-note`）。点名多带本来不带的文件用 `--include <路径>`。
3. **选到正式流程里的某一项**（`status=formal_task`）：原样转述白话——它连着整份合同和排期，对方没有同一版接不上，建议改用全量交接；不打包。一律建议全量交接（整个工作区连着合同和排期一起交），不提供、也不要对她说“连同合同和排期一起交”。
3a. 任务交接**不支持少带**（`--exclude` 会被拒绝并说明）：只带这个任务的记录用到的文件，加上成品页面（HTML / CSS / SVG / Markdown）用到的图片和样式。要去掉被凭据扫描拦下的文件，改文件内容，或确认是误报后登记。
4. 她回“好”（当次原话）之后 `python scripts/jiaojie_dabao.py pack --workspace . --kind task --task <任务编号> --words "<她的原话>" --actor <主控实例> [--to <接手人>] [--include <路径>]... [--accept-problems "<她同意原样交的当次原话>"] [--status-note "<她同意带上的现状补充>"] --json`。结果的处理同第 2 节第 4 步（packed / needs_consent / blocked_credentials / status_note_rejected / version_mismatch）；`blocked_credentials` 里的文件如果她确认不是密码或密钥，用 `python scripts/wubao_dengji.py register --workspace . --path <文件> --field （按文本检查） --words "<她的原话>" --actor <主控实例>` 登记误报（文件没变就放行，变了重新拦，含密钥样式的长串仍拒；英文写法的名字像凭据的不能登记，中文“密码、密钥”等名字内容干净的可以）。

## 7. 任务交接包的导入核心（N4）：给 Agent 看的细节

- 引导层（上面第 5 节）调用 `scripts/jiaojie_jieshou.py`：`check` 只读认出状况代码，`apply --words "<原话>" --actor <实例> [--identity confirmed_same|mixed]` 确认后导入。顺序、幂等和“为什么不破坏记录链”见该脚本顶部说明。单独用这两条命令只在不需要引导的场合（比如排查）。
- 对方要知道的两件事：原来的人说过的“不检查直接发”“最终版”“确认”这类话没有生效，要用得自己再说一次；发客户前的门槛对方和本地做出来的任务完全一样，成品改一个字原来的检核就不再算数。
- 工作包版本只比较三段数字（候选、定稿后缀不算差别）：包里的比这里新要先升级，这里比包新照常接。
- 接收方不信任包：记录摘录行再按白名单筛一遍（发客户记录只收事实类、检核记录只收这个任务的独立检核，决定类一律不收），包里的文件路径先折叠大小写再判，不许落在记录存储位置。
- 转发给对方的话里写了两句提醒：任务包“请不要自己解压，交给 AI 接手”；两种包“只接手认识的人发来的交接包”（压缩包没有加密、没有签名）。
