# 产品矩阵策略

## 依赖与边界

1. 先读 `AGENTS.md`、`project/state.json`，用 `project_handoff.py resume` 看当前计划和任务。本技能只管产品矩阵这类任务：客户要一条产品线、一组礼盒、一套渠道规格，要把“做哪几款、各自扮演什么角色、定什么价、进哪些渠道”说清楚。
2. **本包里不做任何计算。** 成本、利润、净利率、每 500 克零售价、最高出厂价这些数，全部来自产品线测算平台已经算好并保存的结果；工作包不写公式、不写本地复核脚本、不口算、不凭记忆报数。平台数据缺了就写“待平台测算”，不推算、不估一个。
3. 只使用当前项目资料。其他项目只作方法参考，不带入客户名称、数字、认知。合成样例只用虚构名。
4. 方法来自三份真实案例的**结构**（金字塔三层的产品线策略、多维打分加四象限的选品判断、先市场研判再选品的顺序），不含任何客户资料；见 `方法来源.json`。

## 第一步：定起点，建计划

起点二选一，问清楚再建，不替策略师猜：

- **正推**：客户给了成本资料（投料吨价、包材报价等）。建计划时 `cost_sources` 写清客户给了哪些、出处在哪。
- **反推**：客户只给了一个定价锚点（如“12.8 元/斤”）。成本资料一律列“待补”，不得写成已知成本；之后客户补了成本，再把出处记下来。
- **按斤（重量）给的锚点**：先问清每一款是散装还是定量装——散装按斤卖，还是定量装（一袋、一盒固定重量）。散装的直接用平台的散装反推（平台按 500 克算）；定量装的按平台测算技能的提问口径问清每袋（盒）的目标价，**工作包不自己换算**（不把斤价折成袋价）；问不清或平台走不通的款，计划里该款的平台测算标“待平台测算”并写明原因（记在 M6 任务的进展里）。建计划时锚点是按斤给的，`create` 和 `inspect` 会带一句同样的提问提示（`anchor_hint`）。
- 两样都有或都没有：先问策略师，问清再建。

建计划（每个阶段落成一条独立任务，沿用独立任务的版本、检核与交付）：

```
python scripts/matrix_plan.py create --workspace . --actor <主控> --request <请求文件>
python scripts/matrix_plan.py inspect --workspace .
python scripts/matrix_plan.py stages --workspace . --actor <主控> --plan-id <计划编号> --reason "<一句理由>" --remove M2      # 删减阶段；--restore 恢复
```

请求文件字段：`plan_id`、`request_id`、`user_words`（策略师原话）、`goal`、`project_label`，可选 `start`（`forward` 或 `reverse`）、`price_anchor`、`cost_sources`、`deadline`、`remove_stages`（`[{"stage":"M2","reason":"客户已给齐竞品资料"}]`）。

阶段表（每个阶段都可以删减，但不能全部删光；删减要写一句理由，可以一并记策略师原话）：

| 阶段 | 做什么 |
|---|---|
| M1 任务简报与起点 | 起点、客户给了什么、成本资料已提供还是待补、本项目要做哪几步以及每一步做不做的理由 |
| M2 市场与品类研判 | 趋势、竞品、原料成本波动、口味趋势；竞品价格进竞品对照表 |
| M3 选品判断 | 选品打分表加四象限；写明做什么、不做什么 |
| M4 矩阵结构与产品角色 | 按价格带、利润、渠道定角色；金字塔或系列分类；产品矩阵表 |
| M5 产品卡 | 每款一张卡；规格与价格取自平台快照 |
| M6 平台测算 | 正推或反推、多轮方案比较、回读 |
| M7 产品线规划表格 | 平台导出的 HTML 提报与数据存档、登记快照 |
| M8 逐字稿 | 沿用 `proposal-script` |
| M9 HTML 演示稿 | 沿用 `html-deck`、`huashu-design`，产品卡区块绑定平台数据 |
| M10 对外交付 | 沿用对外导出与发客户关口 |

做完一件事，看 `inspect` 列的下一步，把能做的下一个说出来当建议；用户可以不采纳。给策略师说话照 `AGENTS.md` 的三段式。

## 市场与品类研判（M2）

- 沿用 `research-evidence` 的证据登记：竞品的规格、价格、渠道都带日期与来源；查不到就写“未查到”，不编数字。
- 竞品价格进 `templates/竞品对照表.json`（复制到项目里填），填完运行 `python scripts/matrix_plan.py check-competitors --file <文件>`：每个价格要有查到的日期和来源；没有来源的数字不进演示稿，演示稿里用 `data-jingpin` 指到表里的行（见下文“核对”）。
- 检索工具不可用就如实写，不凭印象补。

## 选品判断（M3）

- 复制 `templates/选品打分表.json`，维度可按项目增删，刻度可按维度改，综合判断由策略师写进每个候选的理由，**表里不算总分**。
- 每个候选在每个维度都要有评价、有四象限位置、有“做 / 不做 / 观察”的结论和理由。填完运行 `python scripts/matrix_plan.py check-scoring --file <文件>`，只查填没填全、有没有落在刻度里。
- 做与不做都要写理由；不做的也要留在表里，别删。

## 矩阵结构与产品角色（M4）

- 角色口径（用户 2026-10-13）：
  - **引流款**：价格带低、受众最广，可以不赚钱甚至亏钱，**不设亏损上限**。
  - **利润款**：核心指标是利润最高，比平台算出的**工厂净利率**（用户原话“利潤款看淨利率就好”），不一定是最高价带。
  - **形象款**：包装特别、承担品牌形象。
  - **基础盘**：铺满渠道、保住市占。
  - 角色也要同时看利润率与渠道。
- 矩阵用金字塔（长期品牌资产 / 短期增长 / 基础盘三层之类）或系列分类摆。每款角色要有依据（价格带、利润、渠道）。
- 复制 `templates/产品矩阵表.json` 填：每款的角色、定位、规格、零售价、净含量、主推渠道、表现策略、对应平台品项编号。价格和净含量必须来自绑定的平台快照，不手抄。
- 平台测算完成、登记快照后，运行 `python scripts/juzhen_hedui.py roles --workspace . --matrix <文件>`：标成利润款的工厂净利率低于同组某个非利润款、标成引流款的每 500 克零售价高于同组某个非引流款，会提示“角色与测算不符”，交策略师决定改角色还是改方案。形象款与基础盘不做数字核对。

## 产品卡（M5）与演示稿（M9）

- 每款一张卡：角色、定位、产品、规格、零售 / 促销价、主推渠道、表现策略。
- 演示稿里产品卡区块的数字用属性绑定平台数据：卡片外层写 `data-pingtai-sku="<平台品项编号或款名>"`，卡片里的每个数字所在元素写 `data-field="<平台字段名>"`（如 `retailPrice`、`netWeight`、`netMargin`）。页面类型见 `templates/proposal-deck.html`（产品卡页、金字塔页）。
- 运行 `python scripts/juzhen_hedui.py deck --workspace . --deck <演示稿HTML>`：演示稿数字与绑定快照里平台已保存的数不一致时，报出款名、字段、两边的数值。竞品价格用 `data-jingpin="<竞品行编号>"` 绑定到竞品对照表，没来源的不放行。
- 页面里没绑定的数字，核对帮不上忙：写进演示稿的价格、规格、利润数，都要绑定。

## 接产品线测算平台（M6、M7）

平台是用户另一个项目，由用户持续更新；**本包不复制、不分叉平台的测算技能与说明**。

1. **安装**：去产品线测算网站的“接入 Agent”页，照页上最新说明装连接工具和测算技能。每位策略师用自己的账号在网页上授权。本包不读取、不保存、不打印任何平台登录凭证。
2. **工具名以宿主实际发现为准**。已知的有：`get_identity`、`list_projects`、`get_project`、`get_sku`、`simulate_forward`、`simulate_reverse`、`create_project`、`create_sku`、`update_project`、`update_sku`、`export_project` 等；名单会随网站更新变，别当固定清单。
3. **只读本次任务需要的平台项目**：用户指明了项目就按编号直接读（`get_project`），不调 `list_projects`、不列出全部项目；需要从几个项目里选一个时，先问策略师是哪一个，再按编号读。测算技能的依赖检测、连通测试也照这条，不为“看看连上没有”去列全部项目。
4. **开始前**先调 `get_identity`，核对是谁、什么角色、能看到几个项目，再运行 `python scripts/pingtai_kuaizhao.py identity --workspace . --actor <主控> --username <用户名> --role <角色> --projects <可见项目数>` 登记一条“平台身份核对”记录（只记这几项，不记凭证）。
5. **可以做的**：建草稿项目、改规格、正推 / 反推、多轮方案比较、回读（`get_project`）、导出。写入后一定回读，用回读的数，不用没保存的对话试算。**平台工具返回的原文整段写入文件**（回读结果原样存成 JSON 文件），不手抄、不改写、不挑字段重排；登记快照时会和提报页交叉核对，抄错一个数就登记不上。
6. **禁止调用**提交审核、撤回、修订、删除这几类工具（名字里带 `submit`、`withdraw`、`revise`、`delete` 的一律不碰），即使宿主放行也不调。提交审核、撤回、删除只由策略师本人在网页上操作（用户原话：“可以寫草稿，提交我來按”）。
7. **平台用不了的时候**（没装、没登录、没授权、网站不可用、权限不足）：M6 标“待平台测算”；M2 到 M5 照做；**不给任何利润数字**，不自建公式、不写本地计算脚本、不口算。策略师要求测利润时，回复“需要先登录授权”（或说明是哪一种用不了），然后停在那一步。
8. **登记快照**（M7）：同一次导出的 HTML 提报和 `get_project` 的 JSON 一起存档：
   ```
   python scripts/pingtai_kuaizhao.py register --workspace . --actor <主控> --html <导出的提报HTML> --json-file <回读的JSON文件> --exported-at <导出时间，如 2026-10-13T10:00:00+09:00> --plan <产品矩阵计划编号>
   python scripts/pingtai_kuaizhao.py bind --workspace . --actor <主控> --snapshot <快照编号> --path <成果文件> --kind deck|matrix|other    # 演示稿里有竞品价格时，bind 后面再加 --competitors <竞品对照表>（须在项目文件夹里）
   python scripts/pingtai_kuaizhao.py inspect --workspace .
   ```
   快照记平台项目编号、导出时间、平台更新时间、文件指纹；JSON 一定要用 `get_project` 回读的结果（有品项编号、项目编号、更新时间），导出工具的行数据会被拒。登记前会把提报页“渠道结果对比”表和 JSON **逐款交叉核对**（款名、零售价、出厂价、净利率、净含量、出厂价 / 500g、零售价 / 500g，按提报页两位小数、百分数两位小数比）：对不上会点名哪一款哪一项，提报页里读不出来也不当作一致，都拒绝登记——重新把工具返回原文整段存一份再登记，不要改提报页去凑。`--plan` 写这次快照属于哪个产品矩阵计划（工作区里只有一个计划时可以不写，自动关联；同一份内容再登记带 `--plan` 只补关联）：关联后计划和续做状态里的平台测算显示“已有平台快照，第 N 版”。`bind` 当场按这一次快照核对（演示稿用 `deck`、矩阵表用 `roles`），核对通过才记“已核对”，状态 `bound`；核对没通过照样绑上，但状态是 `bound_unverified`，给策略师说“已绑定，但核对没通过，需复核”。之后平台数据又变了、登记了新快照，绑定旧快照的成果会标“需按新快照复核”；复核后再 `bind` 到新快照。`deck`、`roles` 不写 `--snapshot` 时先看页面里的 `data-pingtai-snapshot`、矩阵表里的 `snapshot_id`，再看这份成果的绑定；工作区里有多个平台项目的快照又没指明用哪个时会拒绝，不替你猜。导出时拿到的下载链接带一次性凭据，用完即弃，**不要写进任何文件**，也不要贴给策略师。
9. **给客户前**：平台导出的提报页上有“负责人”“状态”（草稿、待审核、审核通过等）和“审核意见”（项目被审核过才有），给客户前请策略师看一眼这几项是否保留、对不对（`inspect` 会列出提报里各自在不在、值是什么；发客户登记含这份提报页时也会提醒）。

## 提报（M8—M10）

M8、M9 是计划里的两条独立任务（编号 `<计划编号>-M8`、`<计划编号>-M9`），**不要求品牌屋已确认**，也不挂内部提案的品牌屋、推导、简报三个前置；它们的前置是产品矩阵自己的上游：矩阵表、产品卡、平台快照、竞品对照表。流程沿用现有的：

1. **逐字稿（M8）**：写法沿用 `proposal-script`（每章有转场、能直接念的完整文字、论断来源），存成这条任务的交付物；论断来源指向矩阵表、产品卡、绑定的平台快照、竞品对照表。数字只能来自平台快照，不在逐字稿里自己算。
2. **HTML 演示稿（M9）**：沿用 `html-deck`、`huashu-design` 做页面，产品卡页和金字塔页用 `templates/proposal-deck.html` 里现成的类型；产品卡数字加 `data-pingtai-sku`、`data-field` 标注，竞品价格加 `data-jingpin`。做完先运行上面的 `juzhen_hedui.py deck` 和 `roles`，对得上后用 `pingtai_kuaizhao.py bind --kind deck|matrix` 把演示稿、矩阵表绑到快照（`bind` 当场核对，通过才记“已核对”；演示稿里有竞品价格就加 `--competitors <竞品对照表>`，对照表之后被改也算需复核）。--kind other 只用于不含平台数字的文件：演示稿一律 deck、矩阵表一律 matrix；以前按 deck 或 matrix 绑过的文件、带平台数据标注的 HTML 不能改用 other（程序会拒绝），核对没通过就把数字改对再绑。
3. **独立检核**：逐字稿和演示稿各自交 `independent-review`（独立任务检核，`jianhe_zhunbei.py` 准备）。检核员的清单在原有基础上多三条：**数字与平台快照一致、角色有依据、竞品价格有来源**；不得把品牌屋、推导当缺陷。
4. **策略师确认**：检核通过后交策略师看；她说这版就是最终版，用 `jiaofu_guankou.py final` 记下她的原话。数字、角色、竞品价格里有红灯的，她没拍板前不往下走。
5. **对外交付（M10）**：用 `jiaofu_guankou.py deliver` 登记发客户。有检核通过或策略师说不用检核才能记；另外，交付物里绑定了平台快照的成果如果现在“需复核”（平台数据更新了、上次核对没通过、核对后文件又被改过），会被拦下，要先重新核对再记。平台提报页里的负责人、状态、审核意见，登记时会再提醒一次。

## 对策略师说话

三段说：发生了什么 / 对你有什么影响 / 要你做什么。不出现命令名、字段名、文件路径；“正推、反推”第一次出现时用一句话解释（正推：客户给成本，我们算出该怎么定价；反推：客户给了想卖的价，我们倒推成本做不做得出来）。平台没连上时直说，别报数字。

## 执行契约

- **触发**：客户要产品线、礼盒线、新品线、渠道规格规划，或要把一组产品的角色、价格、渠道说清楚。
- **开始**：先问清起点（客户给了成本，还是给了定价锚点）、客户要的是哪几件事；最多提五个会改变结果的问题。
- **产出**：产品矩阵计划、竞品对照表、选品打分表、产品矩阵表、产品卡、平台快照登记；数字只来自平台。
- **停止**：起点说不清、平台用不了（M6 标待平台测算，其余照做）、数字对不上快照、角色与测算不符而策略师还没决定时，停在那一步并说清缺什么。
- **交接**：逐字稿交 `proposal-script`，演示稿交 `html-deck` 与 `huashu-design`，检核交 `independent-review`，证据交 `research-evidence`。
