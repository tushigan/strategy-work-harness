# 增量报告协议 v2

支持standalone、phase3简报/研究/品牌屋/推导、html品牌屋和phase5逐字稿/演示稿。不是自动内容审稿器，也不是抗本机管理员篡改的身份认证。

1. 阶段首次完整检查，原报告字段之外加入模板所列八项。full 的 base_review=null、changed_scope=[]、reused_coverage=[]。阶段首次 review_purpose=stage，最终=final；HTML/PDF 还须当前全页视觉证据。通过登记后保存完整基线与来源快照，事件返回 baseline 指纹。
2. 同阶段修订准备 target JSON，运行 `python scripts/incremental_review.py --workspace . --target 目标JSON --reviewer 实际独立实例 --change-kind unknown --json`；合成测试才加 `--simulation`。取返回的 changed_scope、reused_coverage、checked_sources_required，不能手填遗漏差异。独立者判明纯局部措辞可用 local_text；strategy/source/numeric/unknown 均扩大复核。
3. 在原报告结构中添加模板八项。base_review 恰含 record_id、evidence:{path,sha256}、baseline:{path,sha256}，引用同任务通过的完整基线事件。review_mode=incremental、review_purpose可为stage/revision/final；完整覆盖链必须成立。changed_scope 使用脚本计算值，包含 files/removed/recheck_sources/reason_codes/coverage_granularity；当前只支持文件级覆盖。实际重读文件写 checked_sources，继承单列 reused_coverage，二者不得重叠。所列实际影响由检核者负责，不以作者自报代替。
4. standalone 保留原九个报告字段；phase5 保留 target、reviewer_instance、status、simulation、scope、assessment、findings、uncovered、checked_sources，assessment 五项及 findings 红黄绿定位规则不变。scope 仍覆盖当前所有必要业务章节。上述八项都必须出现，impact_assessment 恰含 change_kind 与非空 reason。
5. standalone 每个 HTML/HTM/PDF 成品的 visual_evidence 条目含 artifact:{path,sha256}、method 和 pages。每页恰含 page、file:{path,sha256}、observation；HTML section id 必须唯一，无 section 时 document，PDF 页码为字符串。当前全页截图不同且可解码，不复用旧版视觉结论。正式演示继续使用原 visual_evidence 逐页格式与 browser_checks 结果，不能改成 standalone 格式。
6. 基线报告/快照改变、跨任务、模拟用于真实、作者/诊断者自审、遗漏差异或必要读取均拒绝。来源/上游/策略/项目记忆/数字单位改变扩大来源检查；全局样式、字体、页面新增及映射不明全页检查。最终交付完整覆盖链核对、两轮上限、逐份确认、客户批准均保持。

历史旧报告只按旧完整格式回读；新登记的独立任务报告必须使用第2版格式。当前HTML/PDF放行均须绑定当前成品逐页视觉证据（必看页实看 + 程序比对的继承页），不得以旧格式绕过。后续退回、证据不足、撤销或新的完整审核会使旧基线失效；纠正问题后完整独立重审建立新基线，不接受作者自填已解决。继承覆盖保留未解决黄灯意见；没有保存的有效基线不能事后伪造继承。 新的完整独立审稿必须逐项实查纠正后的成品和全部必要原文，不能只填写解决状态。后续退回不会因自填解决事件恢复旧基线。任何模拟图片或字段校验都不证明真实显示正确。


## 累计检核与冻结审查组（本节优先于旧全文/新实例措辞）

先运行 `python scripts/incremental_review.py --workspace . --target 目标JSON --reviewer 实际独立实例 --purpose revision --json`，final用 `--purpose final`；不再要求手动找base-record-id。首次无有效基线返回full；以后默认累计改动和关联影响。unknown保守扩大；独立者已有充分依据判定局部文字时用 `--change-kind local_text`。dispatch_required=false 时直接回读当前报告和覆盖链，不再派审或生成新报告。确认仍核对当前版本，不继承旧批准。若复用依据失效，按返回范围重新检查。

检核请求带 review_target、simulation、change_kind及review_purpose，agent_dispatch.py prepare 会重新计算计划：未变化返回reused且不新增分派；需要审查时 input_files 必须精确对应实际 required 范围，另传完整任务原话与标准。基线/差异/未解决意见只作必要证据引用，禁止复制整段聊天历史或递归审查报告。角色文件仅定义职责；按宿主实际可用能力调用，复用未参与创作的实例时不携带无关聊天。

较大任务且额度允许时，用 `shencha_zu.py create --workspace . --input 组请求JSON --actor 主控` 建2—3名只读组，成员含member_id、role(part/consistency)、scope、paths；唯一consistency成员读取全部本次相关部分以独立判断跨部分一致性。目标绑定冻结版本。create可能直接返回dispatch_required=false。通过 request 动作取得成员最小请求，再用现有prepare/assign/return/complete；使用真实不同执行及宿主实例和调用证据，每份报告另存不可覆盖路径。组内同任务并发仅在冻结计划校验后允许，普通同任务拦截保留。

成员报告包含 target、reviewer_instance、simulation、status、scope、checked_sources、assessment、findings、uncovered；实际读过的原件必须等于成员分工，consistency还须有assessment.cross_consistency文字判断。独立报告与实际调用/返回/回读证据绑定。组 submit 保存每份报告，失败/缺口照实存；merge检查覆盖、意见冲突、独立身份及当前版本，并调用原生登记。合并模板提供原生格式所需的当前视觉证据等字段，不能自行填写另一个通过结论。漏查、失败、冲突、重复实例、来源/记忆变化或中途换版全部阻断；保留原报告，重新核对后建新组，不能删除并发拦截后直接放行。

实际checked_sources、继承reused_coverage、uncovered分别记录。scope列出整条覆盖链的业务章节，不能把继承原文说成这次已读。来源、数字、策略和不明影响扩大；HTML/PDF新版本须有必看页的实际视觉证据，其余页只能是程序按像素比对给出的继承页（v1.7.0，W01）。修订上限、真实来源和当前确认保持。日志从原生计划/分派/返回/合并节点生成模式和原因，无额外逐步日志工具调用。本候选仅作者自测。
