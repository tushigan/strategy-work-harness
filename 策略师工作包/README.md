## 开始工作

1. 解压整个工作包，按项目重命名目录，把它设置为 Codex 或 Claude Code 的工作区根目录。
2. 在 Codex 或 Claude Code 说：“检查工作包环境和项目进度，告诉我缺什么资料。”总控会先执行统一交接/恢复检查，读出独立任务、项目长期记忆、任务关系和操作回执，再检查依赖和记录，不需要你写命令或 JSON。需要把项目交给别人时，移交方生成交接清单，接收方完成回读后再登记接收。
3. 上传合同服务列项 Excel/PDF。先确认列项识别、时间、负责人，再拆任务并生成批量导入 Excel，由人检核后上传项目系统。
4. 后续直接交任务、资料、反馈和明确确认。每个任务先有简报；Agent 保存版本并安排独立检核。上游改动后会核对下游影响，再按授权调整。

## 目录在哪里

```text
AGENTS.md                两边共用的主控规则
CLAUDE.md                Claude 读取共同规则的入口
.claude/                 Claude 的技能、角色和启动入口
.agents/skills/           14 个业务 Skill
.codex/agents/            6 个策略工作角色
.codex/hooks/             Mac 启动检查
.codex/config.toml        本地宿主配置
project/                 当前项目资料、任务、成果、版本与记录
templates/               品牌屋及演示稿模板
scripts/                 登记、版本、检核、生成与移交审计程序
```

`.agents`、`.codex` 和 `.claude` 是固定名称，前面的点不能去掉。访达默认隐藏它们，可按 Command + Shift + 句号显示。不要把开发工作区中的产品需求、开发计划、测试和历史验收案例复制进来。

总控是 project-controller；专业工作由 strategy-author、proposal-author、deck-builder 和 design-expression-reviewer 分工，正式产出和独立任务当前交付物都交 independent-reviewer 中立检核。角色文件只定义职责，总控须显式调用不同实例，并用 `scripts/agent_dispatch.py` 留存交接证据，不会因为目录存在就自动运行；没有独立实例时只能保留待检稿。逐字稿确认后，Huashu 与 `html-deck` 先组织每页要点、表格、图表或本地图片，将画面内容与完整讲者文字分开，再登记为正式 HTML。完成实际浏览器检查、逐页内容与视觉独立检核、策略师确认后可导出 PDF。PDF 另需逐页回读与独立观察；自由多文件和 PPTX 仅为扩展候选，不自动继承正式 HTML 的通过状态。完整交接规则见 [AGENTS.md](AGENTS.md)。

## 当前边界

仅面向 Mac。品牌屋 HTML 可在支持且已授权的浏览器中保存回原文件并保留文件内历史；具体支持范围见对应说明。演示稿浏览器编辑仅是草稿和导出副本。正式采纳画面措辞或样式修改时更新页面方案并重新检核、确认；涉及策略、事实或结论变化时，先回到逐字稿修订和确认，再生成下游新版。

飞书和云端大脑需核实实际账号、权限和回执，安装技能不代表连通；未知结果不重复发送。语音需要可靠文字稿。完整产品矩阵策略另行补足，目前能管理其合同任务及人工交付。

独立检核、策略师确认、客户确认、系统上传和对外发布分别记录。本地验证不证明真实客户批准或平均返工已降至一轮。工作包内记录不是防篡改身份认证，真实客户资料移交还需保密和分发授权。
