# 项目检核与结项运行说明

本入口仅支持 macOS，处理跨阶段影响、人工交付、客户决定、项目报告和结项。它不代替真实客户批准、生产连接验收或返工效果统计；这些事项必须有实际原文、回执或业务证据。

## 自然语言入口

策略师在 Codex 提供资料、反馈和决定，Agent 操作以下命令。不要要求策略师手写程序格式；也不能替策略师编造确认原文。

- “检查整个项目还有什么没做完”：读跨阶段检查、影响扫描和合同结项清单。
- “上游改了，哪些地方要跟着改”：先扫描，列出影响，复用有效范围授权或取得确认后按原流程修订。
- “我收到人工完成的产品方案”：保留原文件，登记实际作者和任务，独立检核后内部确认，再记录交付。
- “客户确认了这些列项”：保存提供的原话，精确绑定列项和当前交付；没有原话就停在待确认。

## 只读检查

```bash
python scripts/review_gate.py inspect --workspace .
python scripts/impact_scan.py --workspace .
python scripts/project_closure.py inspect --workspace .
python scripts/project_closure.py status --workspace .
```

检查返回作者、版本、依赖、报告和两类确认状态。完整引用从实际登记表或来源命令取得，不猜编号。若需把影响结果记入项目，加 `impact_scan.py --record`；空白模板不写业务记录。

上游字节、版本、报告和确认变化均需复核。扫描不会自动覆盖下游。旧报告和确认变成历史依据，不被删除；明确授权对齐后，仍走各阶段原有修订入口和独立检核。
`affected_workflows` 还列出失效交付、客户决定和结项所需的重做步骤。简报同版重新检核也会使旧交付记录失效，不因正文未变而跳过。

## 总控与人工交付

新增登记只接受 `project-summary`、`closure-report`、`external-deliverable` 三类。前两类 `task_id` 固定为 `project`；外部交付绑定真实计划任务，必须另附实际文件。本入口不是品牌屋、逐字稿、演示稿或设计稿原有检查的替代通道。

请求的 `data` 有 `kind/task_id/title/sections`，每章有 `id/title/text`。`dependencies` 为完整上游版本对象；计划由脚本自动绑定，外部交付还自动绑定本任务已检核的简报。`source_paths` 是包内实际原文的相对路径。修订另有 `revision.base/reason/changes`；上一轮修订未独立复核不能继续，合法的退回报告允许改稿，不要求旧稿先通过。第三轮起还须上一版的 `allowance_id`。

```bash
python scripts/control_artifacts.py publish --workspace . --request 请求.json --actor 实际作者实例
python scripts/control_artifacts.py sources --workspace . --key project::project-summary
python scripts/control_artifacts.py review --workspace . --key project::project-summary --evidence 独立报告.json
python scripts/review_gate.py confirm --workspace . --target 当前引用.json --evidence 策略师原话.txt --actor 确认者
```

报告包含精确 `target`、实际 `reviewer_instance`、明确 `simulation`、`status`、`scope`、`assessment`、`findings`、`uncovered` 和 `checked_sources`。五项判断为 `task_fulfilment/evidence_reasoning/counterevidence/role_boundary/uncertainties`，红黄绿意见带 `location/requirement/evidence/impact/action/decision_owner`。遗漏原文或章节必须列为 `source:路径`、`scope:编号`，不能通过。

作者与检核者必须真实分开，脚本仅阻断已记录的相同实例，不提供身份认证。通过后仍须策略师确认；有黄灯保留 `passed_with_yellow`。任何新版或同版新报告均不能沿用旧确认。两轮后人工增加一轮：

```bash
python scripts/control_artifacts.py allow-more --workspace . --key project::project-summary --evidence 追加授权.txt --actor 策略师
```

独立报告不能填写系统生成的记录编号、登记时间或归档依据。策略与品牌屋产出的策略师确认同时绑定报告编号和文件指纹；旧确认没有指纹或与最新报告不符时，只保留历史，不自动补成有效。应回读当前报告及其黄灯，由策略师重新明确确认，不改写旧确认原文。

## 项目结项

调研分析、品牌屋初稿、内部提案继续使用原任务完成入口。其他人工任务的 `deliver` 请求为 `task_id` 和非空 `outputs` 完整引用列表，要求本任务简报有效、实际交付已检核和内部确认。交付记录绑定简报版本及最新检核；简报换版或重新检核后须重新核对，旧记录不自动补成有效。设计任务须包含已逐页检核的设计提交，不能只交文字摘要。设计稿先由 `design-expression-reviewer` 提供逐页策略诊断候选，再由不同的 fresh `independent-reviewer` 重新读取原件、简报、逐页图和候选，使用现有 `design-review` schema 与命令形成最终报告。

```bash
python scripts/project_closure.py deliver --workspace . --request 交付请求.json --evidence 交付原话.txt --actor 策略师
python scripts/project_closure.py client-confirm --workspace . --request 列项请求.json --evidence 客户原话.txt --actor 实际客户确认者
python scripts/project_closure.py inspect --workspace .
python scripts/project_closure.py report --workspace . --actor 实际总控实例
```

列项请求为 `{"item_id":"实际列项编号"}`。客户退回使用 `client-reject`，不是删除旧确认；在相反决定之后再次提交同一句原话也要形成新事件。只有所有列项已交付且当前客户确认有效，才生成结项报告。客户门禁仍要求有效的内部确认，总控报告另派独立实例检核，再由策略师确认，最后：

```bash
python scripts/project_closure.py close --workspace . --evidence 结项决定.txt --actor 策略师
python scripts/project_closure.py refresh --workspace .
```

结项后修改会使记录进入 `change_pending`；刷新时保留原结项并追加变更，重新对齐、检核和客户确认，不覆盖历史。复制后先运行检查，不只读 `state.json` 缓存。

所有 `--simulation` 仅用于已隔离的 `test_mode: true` 合成案例。真实项目不能为放行修改 `test_mode`。

## 外部与移交

外部连接按 `外部连接说明.md` 和 `knowledge-connectors` Skill 操作。未配置、无权限和未知结果如实记录，未得到用户授权不得回传。

打包审计及复制按 `工作包移交说明.md`。凭据、个人运行环境和真实客户资料不进入通用模板；接收者自行安装依赖并授权。运行缓存可明确排除，失败报告、黄灯与版本历史不可排除。

## 本版效率与增量规则（适用时优先于上文完整读取的通用措辞）

日常续做只运行 `python scripts/project_handoff.py resume --workspace . --json`。它只读记录，核对当前任务、来源、记忆、有效分派及代码/双宿主完整性；默认输出摘要，省略数量明确显示，需展开用 `--details`。当前错误不能靠摘要隐藏；它不是正式移交通过。正式移交保留 `inspect/prepare/accept` 的全量清单检查，不将 Hook 的结构提示当业务验收，不在只读启动中使用 `--refresh` 或 `--record`。

独立任务、正式逐字稿和正式 HTML 演示稿支持第 2 版报告协议：阶段首次与最终交付的来源与数字仍完整审稿（视觉部分按 v1.7.0 W01：阶段首次全页，最终交付只看变化页）；同阶段修订可使用有效、通过的完整独立基线。规则及空白模板见 `.agents/skills/independent-review/references/增量报告协议.md`、`.agents/skills/independent-review/templates/增量报告.json`（Claude 对应同技能目录）。其他阶段、设计返回稿及总控产出仍完整审稿。

基线必须绑定同任务完整报告、不可覆盖的全部来源快照、版本、项目记忆及独立性排除项。当前文件重新核对指纹；增量计划由 `incremental_review.py` 计算累计差异。检核者读取 `checked_sources_required` 的真实原文及成品，逐项核实实际影响；`reused_coverage` 单列继承覆盖，绝不写成这轮已读。CLI 默认 `--change-kind unknown` 扩大检查；仅在独立者有依据判定纯局部措辞时使用 `local_text`。不得仅据作者标签缩小范围。

来源、数字/单位、策略意思、记忆或上游变化扩大来源复核；范围不明也扩大。HTML/PDF 新版的视觉检查按页增量（v1.7.0，W01）：程序在同一渲染环境下逐页无损截图、按像素逐个比对上一份通过检核所绑定的版本，像素完全相同的页继承上次视觉结论（记“继承视觉覆盖”，不写成本轮已看），其余页必看；没有基线、旧报告无像素指纹、环境不同、字体未加载、页面脚本改变、渲染不稳定（动画等）一律必看，页数变化从第一处不一致起其后全部必看，阶段首次检核仍全页。对外交付前（final）视觉部分同样只看变化页。来源与数字的原文覆盖仍按文件级规则，不因视觉继承缩小。正式演示稿仍运行 deck-browser-check 并绑定本次真实截图、导出重开与离线结果。没有真实渲染不得声称视觉通过；合成只用于 test_mode 测试。

增量报告是新的独立判断，不继承通过、人工确认或客户批准；仍禁止任何历版作者及诊断者自审。上一轮独立者可继续审未参与创作的修订，角色名不证明独立性，主控须保留真实实例证据。两轮自动修订上限、当前确认及原有门禁均保留。旧报告可按旧完整格式回读；没有保存的有效基线不能事后伪造继承。
