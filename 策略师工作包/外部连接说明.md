# 外部连接说明

本模块只处理外部读取、云端大脑回传和连接审计，不修改检核、确认、版本或项目完成状态。
宿主技能已安装不等于账号已登录、有权限或服务可用。每次业务调用必须检查当前账号、项目归属、读取或回传授权及实际返回。

## 本地入口

在工作包根目录运行：

```bash
python3 -B scripts/knowledge_connectors.py inspect --workspace .
python3 -B scripts/knowledge_connectors.py read --workspace . --request project/read.json --explicit-read
python3 -B scripts/knowledge_connectors.py prepare-write --workspace . --request project/write.json
python3 -B scripts/knowledge_connectors.py write --workspace . --request project/write.json --authorization project/authorization.json
python3 -B scripts/knowledge_connectors.py reconcile --workspace . --request-id REQUEST_ID --explicit-read
```

`--request -` 和 `--authorization -` 可分别从标准输入读取 JSON，不能同时使用。
所有输入文件引用必须在当前工作包内；不接收任意命令、程序路径、服务地址或凭据。
自然语言任务由主控整理为上述请求，不要求策略师手写 JSON。

Python 接口在 `knowledge_connectors` 中：

- `inspect(root)`：只读本地状态、宿主安装情况和连接日志，不联网、不写文件。
- `read(root, request, explicit=False, transport=None)`：必须明确允许读取。
- `prepare_write(root, request)`：生成稳定源编号、请求编号和授权所需指纹，不写文件。
- `write(root, request, authorization, transport=None)`：仅实现 shared-memory 回传。
- `reconcile(root, request_id, explicit=False, transport=None)`：只回读，不重发。

空工作包可检查安装情况，但拒绝读取、回传及任何连接日志写入。外部操作前必须先通过 `task_context.py save-identity` 建立项目编号、项目名、客户名和品牌名；合同计划可以仍是未初始化，最小项目身份不代表已经立项或确认合同。

工作包内的 `project-memory.jsonl` 是当前项目的本地长期记忆，随目录交接；shared-memory 是外部云端来源，两者分开。启动先采用本地已确认事实，再按授权读取外部资料；外部结果有冲突时保留冲突并核对，不能静默覆盖本地纠正。本地记录不会自动上传云端。

## 读取请求

```json
{"provider":"shared-memory","operation":"context","mode":"hard","query":"当前项目研究依据"}
```

`mode` 为 `hard` 或 `soft`。范围由当前 `project/state.json` 的项目编号、项目名、
客户名和品牌名确定；请求可附 `scope`，但必须与当前状态完全一致。
shared-memory 使用宿主脚本的 `context --json`，不能用压缩 Markdown 代替逐条来源归属。

硬连接逐条核对返回资料的项目、品牌、客户；缺少归属、存在冲突或只有检索命中都不算本项目事实。
软连接只取结构化的 `methodology`、`link_reason`、`applicable_when`、
`not_applicable_when`，四项均须存在。不会导入他客正文、案例数据或把方法参考变成项目证据。
归属缺失时宁可少取，主控可核对原始来源后重新提供明确绑定。

飞书支持：

- `lark-drive / search`：`query`，可选 `container_id`（项目文件夹编号）。
- `lark-task / search`：`query`。
- `lark-minutes / search`：`query`；`lark-minutes / transcript`：`resource_id`。
- `lark-doc / fetch`：`resource_id`（文档资源编号，不接受带访问参数的链接）。

搜索只读一页，明确返回是否还有后续页；不会将第一页称为全部资料。
可用返回的 `page_cursor` 显式请求下一页，不把分页游标写入审计。
搜索结果须有本地绑定才返回正文；未绑定项仅记排除数量，不落他客标题或正文。
详情读取必须先提供 `bindings`：

```json
{"provider":"lark-doc","operation":"fetch","resource_id":"SYNTHETICDOC",
 "bindings":[{"resource_id":"SYNTHETICDOC",
 "scope":{"project_id":"synthetic","project_name":"Synthetic","client_name":"Synthetic","brand_name":"Synthetic"},
 "evidence":{"path":"project/ownership.txt","sha256":"文件的SHA256"}}]}
```

绑定依据必须是项目内已存在、指纹吻合的实际归属记录，不能凭标题或邻近目录猜测。
妙记仅取逐字稿，保留时间和不确定说话人；在临时隔离目录读取后清理，不把命令生成文件直接放进工作包。
**凭据只放工作包外**（v1.7.5）：飞书上传、妙记转写等用到的登录凭据（token、密钥、密码、授权文件）只放在工作包之外由宿主或本机工具保管，不复制进项目目录、不作为来源或证据登记；`jiyibi.py` 记一笔时证据文件名或内容像凭据会被拒收，启动检查也会拦下项目里的疑似凭据文件。
文档里的表格、画板及关联纪要不在此读取器内自动下钻，返回缺口交主控按对应宿主技能处理。

## 授权回传

```json
{"provider":"shared-memory","source_key":"synthetic-note-v1",
 "title":"合成示例","content":"明确授权的内容","kind":"conversation","run_dream":false}
```

先 `prepare-write`，把返回的 `request_id`、`payload_sha256` 和 `scope` 放入授权对象：

```json
{"approved":true,"actor":"实际授权人","request_id":"准备结果中的编号",
 "payload_sha256":"准备结果中的指纹","scope":{},
 "evidence":{"path":"project/consent.txt","sha256":"授权原文的SHA256"},"simulation":false}
```

授权原文须明确覆盖目标、内容、范围和可选提炼操作；布尔值不能代替真实用户同意。
授权绑定精确请求，内容变化必须重新授权。程序校验文件及指纹，不提供对恶意本地改文件者的身份认证。
不自动执行 Skill 中的默认写记忆、采用反馈、账号申请、授权扩权或付费操作。

发送前先原子记录 `pending`。成功回执也必须再按同一个源编号回读，
核对源编号、完整内容、标题、项目和品牌，才能记 `synced`。
超时、空回执、无法解析、回读截断、权限不足、内容不符或服务不可用都不能视为同步成功。
同一请求跨进程、复制恢复后不会再次发送；已有待核验请求只回读，成功请求直接返回原结果。
同一源编号换内容会被拒绝，需要明确的新版本 `source_key`，不能为绕过未知结果随便换编号。
即使回读未找到，也不自动重传：需人工查明服务端结果，本接口不提供强制重试开关。

## 审计与降级

独立日志为 `project/records/connector-events.jsonl`，配套本地互斥锁避免并发重复发送。
日志只保留来源散列编号、获取时间、原始资料时间（缺失则 unknown）、范围、状态、
内容指纹和最小回读结果，不保留正文、命令、原始 stdout/stderr、宿主路径或凭据。
读取结果的 `items[].locator` 只在调用返回中保留原始来源编号，方便当次核对，不写入日志；
日志不是正文缓存，复制后需要原始读取请求或归属依据才能再次取得外部资料。
`inspect` 同时显示最近结果和所有未核验回传；历史成功不等于当前账号权限仍有效。
日志损坏、换项目或生产包中混入模拟记录时停止外部操作，不自动修日志、不覆盖历史。

无权限、未安装、服务不可用和返回不明分别返回 `denied`、`unavailable`、`unknown` 等状态；
结果包含 `local_work_can_continue`，但缺失外部证据不能编造。
程序不写 `state.json`，不登记业务确认，也不修改其他阶段模块。

真实项目禁止注入模拟传输、模拟授权和模拟返回，不能为跳过检查改变 `test_mode`。命令行没有模拟开关；合成测试记录不能作为真实连接或业务批准证据。

## 已核对与限制

实现依据：已安装 shared-memory 2.1.0 的脚本和 API 说明，飞书共享、云盘、
妙记、任务、文档技能，以及本机 `lark-cli` 的对应只读帮助和内置文档。
不复制宿主技能、脚本、配置或凭据。实际命令只使用允许列表和参数数组，不通过 shell 拼接。
远端接口结构若不符合已知契约，保留 unknown，不靠退出码或猜测宣称成功。
敏感信息检测是保守的常见凭据/路径拦截，不替代人工保密审查。
本版只面向 Mac。真实账号读取、回传及线上权限均须在实际项目中另行核对；连接返回不代替独立业务检核或客户批准。

## 产品线测算平台（v1.7.6）

产品线测算平台是用户另一个项目（网站），本包只写“何时调用、调用前后登记什么”，**不复制、不分叉网站的测算技能与平台说明**；以网站为准。

- **安装（v1.7.6 写法，仍可用）**：去网站的“接入 Agent”页，照页上最新说明装连接工具与测算技能。每位策略师用自己的账号在网页上授权；工作包不读取、不保存、不打印平台登录凭证，回归与走查都不碰凭证。
- **第一次连接（v1.7.7，P10）**：网站网址 `https://120.76.179.118`（用户同意公开）。策略师说“帮我连产品线网站”，或产品矩阵要用平台而会话里没有平台工具时，AI 按 `product-matrix` 技能“第一次连接产品线网站”一节做：先查（会话里有没有平台工具、测算技能在不在、本项目有没有平台身份记录），都在就只报“已连上”；没连上时每次只读访问网站公开安装清单 `https://120.76.179.118/api/agent-install/manifest` 取连接参数与测算技能的下载地址、大小、校验值（包内不写死），AI 自己认出宿主（Codex 或 Claude Code）、一句白话征得同意后照对应步骤装，**登录由策略师本人在弹出的网页里做**，装完重新打开对话；连好后只调身份核对、登记，不列出全部项目；看得到 0 个项目或账号不对时到网站“管理连接授权”页撤销重登。续做状态：建过产品矩阵计划、还没有身份记录时提醒一行“说一句‘帮我连产品线网站’，我带你连”，登记后显示“产品线网站：已连上（账号、身份、日期）”。Claude Code 的技能目录、加连接与登录入口按官方文档查证（2026-10-14），桌面版的登录入口官方未写明，待查证，见技能。
- **工具名**以宿主实际发现为准（已知有 `get_identity`、`list_projects`、`get_project`、`get_sku`、`simulate_forward`、`simulate_reverse`、`create_project`、`create_sku`、`update_project`、`update_sku`、`export_project` 等，会随网站更新变）。
- **开始前**调 `get_identity` 核对身份和可见项目数，运行 `pingtai_kuaizhao.py identity` 登记一条“平台身份核对”（只记用户名、角色、可见项目数）。
- **可以**建草稿、改规格、正推 / 反推、多轮方案比较、回读、导出；**禁止**调用提交审核、撤回、修订、删除类工具，这几件只由策略师本人在网页上做。
- **用不了时**（没装、没登录、没授权、网站不可用、权限不足）：测算一步标“待平台测算”，其它阶段照做，不给任何利润数字。
- **快照**：同一次导出的 HTML 提报与回读的 JSON 一起用 `pingtai_kuaizhao.py register` 登记；导出时的下载链接带一次性凭据，用完即弃，不写进文件。
- **边界**：平台导出的数据格式变了就报“平台数据格式变了，按平台当前说明核对”，不推算、不猜字段。真实平台走查需要策略师本人登录，不在回归里做。
