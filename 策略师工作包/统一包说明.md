# 策略师统一包 1.5.0 · 手动改稿与程序登记候选

以原 Codex / Claude v1.0.2 工作包为基础，保留 14 个业务技能、6 个角色和原有项目流程。适用 Mac 上的 Codex 与 Claude Code；Claude 网页聊天不属于本包运行环境。

## 怎么用

1. 解压后复制“统一包”整个文件夹，按项目改名。不要进文件夹只复制看得见的内容；必须保留 `.agents`、`.codex`、`.claude` 三个隐藏目录。
2. 用 Codex 或 Claude Code 打开这个项目文件夹，新建会话，说：“检查工作包环境和项目进度，告诉我缺什么资料。”遇到宿主的目录信任提示，按实际情况确认。
3. 按需提供任务和原始资料。登记、检查和交接由助手运行，不要求你写命令。
4. 换工具前让当前助手保存成果、任务进度和下一步，再结束当前写入。另一个工具打开同一个目录，说：“读取项目交接和当前任务记录，继续工作。”不要让两个主会话同时修改同一项目。

账号、浏览器、外部工具、聊天历史和各宿主个人记忆不会自动同步。项目状态通过 `project/records/`、任务版本和真实文件接续。项目已有记录不会因换工具重置；不同客户各用一个独立副本。

已有项目不要直接覆盖。先备份，再合并规则和配置，保留真实业务记录。统一包不是全局安装包，不会替换个人 Codex / Claude 设置，也不会自动上传、发布或写云端记忆。

## 检查和维护

日常使用无需同步或安装技能。规则以 `AGENTS.md` 为准，`CLAUDE.md` 引用它；共同技能源在 `.agents/skills/`，共同角色源在 `.codex/agents/`。Claude 的入口是由源生成的普通文件，复制到别处也不依赖原路径。

维护者更改源后运行（Python 3.11+）：

```bash
python3 -B scripts/sync_hosts.py sync --workspace .
python3 -B scripts/check_package_integrity.py --workspace . --json
python3 -B scripts/validate_project.py --root . --json
python3 -B scripts/project_handoff.py inspect --workspace . --json
```

同步会拒绝覆盖单独修改的 Claude 副本；先核对并合并改动。删除技能或角色也须明确处理旧副本，不自动删除别人工作。共同源仍保留旧路径，原有脚本和业务引用不需迁移。

正式空白包复制继续用原来的 `scripts/package_audit.py prepare-copy`。发布清单记录发行时内容；维护包后旧发行清单可能失效，不能修改指纹来冒充原发行版本。本次制作记录、作者测试与宿主发现证据放在压缩包外的“验收”目录，空白项目不含测试任务或模拟确认。

两边均配有启动钩子，但不同版本、信任设置可能影响自动执行，所以共同规则也要求助手主动检查。角色文件不等于已经调用独立实例；无独立实例时保留待检稿，不能作者自审通过。

## 保留的业务要求

合同、独立任务、研究证据、品牌屋、逐字稿、演示稿、版本、独立检核和客户确认仍按原流程分别记录。本次没有替换业务方法，也没有代用户或客户确认成果。原包的 Python、Node、表格和浏览器依赖继续按 `运行环境与命令.md` 检查，需要哪项再准备哪项。

## 本候选的新增用法

用户改过文件时，助手先展示程序从真实快照算出的差异，再按当前观察版和已有明确授权登记。进度只补改动字段；成果用显式身份和前后版关系登记。旧稿、普通过程与当前业务依据分别保留，过程里的业务决定仍须列为有效依据或成果依赖。版本号与校验由程序生成。

作者修改走“读修改前快照→写专属候选→实际回传→主控回读→续接登记”。用户同时改稿时双方保留，不能为了通过校验再派作者重写相同成果。宿主调用必须有实际工具证据；凭证格式通过不等于已证明真实调用。

用户要求换对话或交接时，运行 `project_handoff.py summary` 保存程序事实。相同状态复用摘要，人工采用、独立复核、历史通过、未执行和冲突分别显示；正式移交继续用 inspect/prepare/accept。日志默认采集新增操作、必要扩大原因及实查/继承计数；复盘仍只在请求时生成。

本候选只完成合成作者检查和有限只读阶段复核，最终原规划者验收待完成。真实模型、跨宿主全流程、自动Hook及客户体验没有本轮证据，不是正式发布。
