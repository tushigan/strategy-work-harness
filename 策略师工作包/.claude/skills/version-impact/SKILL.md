# 版本与影响

## 执行契约

- **触发**：任何正文、简报、来源、HTML 手工编辑、设计返回稿、反馈修订、回退、恢复或结项后的新变更都要先做影响检查；只查资料而未改变项目文件时不追加空记录。
- **开始**：先读取真实文件、当前版本、来源、反馈、报告、确认和结项记录，再运行 `python scripts/impact_scan.py --workspace .`；不以 `state.json`、`dependencies.json` 或聊天摘要代替实际文件。
- **产出**：变更文件、直接/间接受影响产出、失效报告/确认/交付/客户决定/结项记录、需要重新走的流程、所需人工授权和当前仍可继续的工作。检查结果要绑定本次实际扫描。
- **停止**：发现文件缺失、摘要与原文指纹不一致、存在未完成写入、对象归属不清或授权范围不清时停止覆盖和下游生成，保留现状并列出恢复或确认动作。
- **交接**：把每个受影响对象交回它原本的 Skill 修订；品牌屋回 `brand-house`，逐字稿回 `proposal-script`，演示稿回 `html-deck`，设计稿回 `design-expression-review`，结项回 `project-control`。本 Skill 只判断影响，不代替这些流程写新内容。

## 判断路径

先区分变化类型，再判断影响，不把所有变化一律当成同样严重：

1. **策略正文、证据或任务简报变化**：相关分析、品牌屋、推导、逐字稿、演示稿、设计简报和设计检核均可能失效；先重做上游，再按依赖顺序重新检核和确认。
2. **只改 HTML 样式或布局**：不自动判定策略正文变化，但必须重新回读实际 HTML、显示和版本绑定；若编辑同时改变文字，则按正文变化处理。
3. **来源、原文或来源指纹变化**：重新检查引用、反证、结论强度和跨项目越界；同版新报告也不能自动继承旧确认。
4. **设计返回稿变化**：保留旧提交和报告，登记新提交，重新逐页检查；不能只替换文件名或复用上一版红黄绿结论，不沿用旧报告。
5. **回退或恢复**：回退本身也是新版本，保留旧版本、黄灯、反馈、修订次数和原决定；恢复不能恢复旧批准或绕过当前授权。

执行顺序是：保留旧版本 → 扫描并记录影响 → 取得需要的对齐授权 → 从最上游变更点重新修订 → 按依赖顺序独立检核 → 重新确认 → 刷新结项状态。最多两轮自动业务修订仍未通过时交人工；额外一轮必须绑定上一轮记录，不换作者或清零计数。结项后运行 `python scripts/project_closure.py refresh --workspace .`，新变更不能覆盖原结项记录。

## 字段含义

- `changed_files`：字节改变或缺失的实际文件。
- `affected`：直接和间接受影响的产出及重做步骤。
- `invalidated_records`：需要失效并重做的报告、确认、交付、客户决定和结项记录；历史只保留，不删除。
- `affected_workflows`：受影响的交付、确认和结项流程；即使正文没换版，同版新检核也可能使旧确认失效。

文件系统不提供独立身份认证，主控必须实际调用未参与写作的 fresh 检核实例。`--record` 只在本次影响结果需要进入项目记录时使用，连续状态无变化不重复追加；空白项目不写示例记录。

## 本版效率与增量规则（适用时优先于上文完整读取的通用措辞）

日常续做只运行 `python scripts/project_handoff.py resume --workspace . --json`。它只读记录，核对当前任务、来源、记忆、有效分派及代码/双宿主完整性；默认输出摘要，省略数量明确显示，需展开用 `--details`。当前错误不能靠摘要隐藏；它不是正式移交通过。正式移交保留 `inspect/prepare/accept` 的全量清单检查，不将 Hook 的结构提示当业务验收，不在只读启动中使用 `--refresh` 或 `--record`。

独立任务、简报、研究准备/证据/分析、品牌屋正文/HTML、推导、正式逐字稿及演示稿支持第2版报告协议：首次建立完整基线，此后默认计算累计差异；当前版本和报告有效且未变化直接复用，最终交付核对完整覆盖链，不因用途为final强制全文重读。规则及空白模板见 `.agents/skills/independent-review/references/增量报告协议.md`、`.agents/skills/independent-review/templates/增量报告.json`（Claude 对应同技能目录）。合同/排期、设计返回稿及总控产出仍按原门禁检查。

基线必须绑定同任务完整报告、不可覆盖的全部来源快照、版本、项目记忆及独立性排除项。当前文件重新核对指纹；增量计划由 `incremental_review.py` 计算累计差异。检核者读取 `checked_sources_required` 的真实原文及成品，逐项核实实际影响；`reused_coverage` 单列继承覆盖，绝不写成这轮已读。CLI 默认 `--change-kind unknown` 扩大检查；仅在独立者有依据判定纯局部措辞时使用 `local_text`。不得仅据作者标签缩小范围。

来源、数字/单位、策略意思、记忆或上游变化扩大来源复核；范围不明也扩大。HTML/PDF 新版的视觉检查按页增量（v1.7.0，W01）：程序在同一渲染环境下逐页无损截图、按像素逐个比对上一份通过检核所绑定的版本，像素完全相同的页继承上次视觉结论（记“继承视觉覆盖”，不写成本轮已看），其余页必看；没有基线、旧报告无像素指纹、环境不同、字体未加载、页面脚本改变、渲染不稳定（动画等）一律必看，页数变化从第一处不一致起其后全部必看，阶段首次检核仍全页。对外交付前（final）视觉部分同样只看变化页。来源与数字的原文覆盖仍按文件级规则，不因视觉继承缩小。正式演示稿仍运行 deck-browser-check 并绑定本次真实截图、导出重开与离线结果。没有真实渲染不得声称视觉通过；合成只用于 test_mode 测试。

增量报告是新的独立判断，不继承通过、人工确认或客户批准；仍禁止任何历版作者及诊断者自审。上一轮独立者可继续审未参与创作的修订，角色名不证明独立性，主控须保留真实实例证据。两轮自动修订上限、当前确认及原有门禁均保留。历史旧报告只按旧完整格式回读；新登记的独立任务报告必须使用第2版格式。当前HTML/PDF放行均须绑定当前成品逐页视觉证据（必看页实看 + 程序比对的继承页），不得以旧格式绕过。后续退回、证据不足、撤销或新的完整审核会使旧基线失效；纠正问题后完整独立重审建立新基线，不接受作者自填已解决。继承覆盖保留未解决黄灯意见；没有保存的有效基线不能事后伪造继承。

## 本轮程序协议补充

本候选显式artifact_versions前后版与dependencies决定当前范围；未知映射/丢依赖明确扩大。历史及普通过程不自动改成当前批准，过程中的业务决定不可遗漏。

J01—J04补充：仅在完整稳定声明、明确前后版及同一有效完整基线成立时，局部来源变化必查该来源、受影响成果和必要依据，独立未变成果/依据列继承。共同来源/业务决定、数字/单位/否定、全局策略、未知身份、缺失声明或删边删来源保持扩大，不能把未声明当无依赖。手改接纳的preview须观察被替换原件与候选；分派/basis/续接事件绑定同任务，成功重试不新增修订。事实交接和resume使用同样的任务选择；正式与独立同名时明确formal:T或standalone:T，不猜归属。
