# 项管模板与 Excel

## 当前能力

只在工作包内运行，使用 `运行环境与命令.md` 的入口。
不连接项目管理网站，不自动下载所谓最新版，不上传、不试探系统去重规则。
基线是已核实的 35 列、三个工作表；每个项目仍需登记策略师提供的模板。

## 收到模板

运行 `compare_import_template.py` 原样归档和生成差异记录。
逐一核对工作表、列顺序、批注、必填、条件必填、字典、下拉、默认人名和说明。校验开关、错误/输入提示、公式及联合范围也纳入比较，不能只看选项。
文件指纹改变不一定是规则改变，但不能仅凭同名文件视为同版本。

已知基线可使用已验证适配器。规则变化默认停止：

- 字段改名/删除/新增须先改适配器和测试，不能猜映射。
- 现有字段变成必填、选项删减、默认人员变化，要说明对当前任务的影响。
- 含义不明或说明和下拉冲突时，请策略师核对新模板规则。
- 新版适配需要另一个实例的检核、策略师明确确认原文和绑定模板指纹的证据文件，不能自己造一份“已确认”文件。

新模板不会改写已确认的任务和历史 Excel。需要修订时读取原任务、保留编号和内容，形成新版本再检核。

## 生成

只有合同和排期均已独立检核、人工确认，且当前模板有效、规则检查通过时，才能运行 `export_gantt.py`。
生成结果仍为 Excel 候选，不是可上传的最终文件。

程序实际读取源模板，保留三个工作表、35 列、说明、字典、表头批注和完整数据校验，清除主表示例。Artifact Tool 制作主体，未完整保留的校验节点由结构化 XML 恢复并回读，不重复添加半天规则。
日期使用真实 Excel 日期，半天用上午/下午；多人统一中文分号。
任务编号、合同对应和依赖保留在工作包，不能擅自加列或宣称系统已导入依赖。
每次导出记录模板指纹、计划版本和适配器版本；超出 1000 行时延展工作簿校验，不等于系统容量已验证。

## 独立检核和人工确认

显式调用另一个 fresh 实例读取：

- 原合同、已确认识别结果、计划和版本依赖；
- 实际导出的 XLSX（不是只读生成参数）；
- 导出检查记录中的全部显示图及模板。

核对服务覆盖、四节点、所有行数据、必填和默认影响、日期/半天/依赖、多项目公共信息、示例残留、字段顺序/校验、文字是否遮挡截断。
报告 `checked_sources` 必须覆盖这些资料，附 `visual_assessment` 的实际观察结论。
有红灯退回，资料不足不能通过；黄灯写清影响让策略师决定，不以“脚本成功”替代检核。

登记独立报告后，请策略师确认明确文件版本。只有状态命令显示 `ready_for_manual_upload` 才可交给策略师人工上传。
测试项目只显示 `test_ready_not_for_upload`，严禁上传。

## 失败和更新

渲染失败时原 Excel 仍是草稿，可用 `export_gantt.py --resume-checks` 对同版本重做检查，不重新生成或消耗修订次数。
修改 Excel 请回改语义任务输入后生成新版本，不直接覆盖归档文件。
程序首次生成只记录未上传，不提供自动上传或伪造成功的开关。策略师实际上传后另行留存系统结果；重跑和恢复时保留已有结果，未知或失败先查系统现状，不盲目重传。
本版只面向 Mac；真实系统导入只有取得实际回执后才能声称通过。

## 执行契约

- **触发**：合同识别和排期已确认，且收到当前项管 Excel 模板或要求比较模板版本时触发。
- **开始**：先登记模板文件指纹、工作表、字段和规则差异；模板不明确时停在差异报告。
- **产出**：生成的是与模板绑定的候选 Excel、结构化检查报告、渲染/可读性证据和可上传状态，不是“已上传”。
- **停止**：模板规则变化未确认、合同或排期未确认、红灯、资料不足或实际导出文件未回读时，禁止进入人工上传。
- **交接**：策略师确认当前文件后，由人上传系统并回传系统结果；未知结果先核对，不重传。
